## Deployment options

- **Long polling** (default): `python main.py` — works behind NAT, no public IP needed.
- **Webhook**: `python main.py --webhook` — needs `WEBHOOK_URL` + `WEBHOOK_SECRET`; the secret
  token header `X-Telegram-Bot-Api-Secret-Token` is verified on every request. 
- **systemd** (Linux): unit file in `deploy/accounts_market.service` — copy to
  `/etc/systemd/system/`, then `systemctl daemon-reload && systemctl enable --now accounts_market`.
- **pm2** (Termux/Linux with Node): `pm2 start main.py --interpreter python3.11 --name accounts_market`.
- **Multi-worker webhook**: use the Redis state backend so workers share sessions.

Graceful shutdown (SIGINT/SIGTERM) closes the database, stops the scheduler, closes the HTTP
client and disconnects Telegram.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ConnectError: [Errno 7] Couldn't connect to server` / Broken pipe on Termux | DNS problem. Run: `pkg install resolv-conf` then as root `echo 'nameserver 8.8.8.8' > $PREFIX/etc/resolv.conf; echo 'nameserver 8.8.4.4' >> $PREFIX/etc/resolv.conf; chmod 644 $PREFIX/etc/resolv.conf` (scripts/termux_install.sh does this for you). |
| `PTBUserWarning: The 'per_message' parameter is not set` | Only applies to hand-written ConversationHandler bots. This generator never emits ConversationHandler — the universal state engine routes callbacks, so the warning cannot appear. If you added one manually, set `per_message=True` whenever entry_points include a CallbackQueryHandler. |
| `MappedAnnotationError` / SQLAlchemy annotation errors | Use `Mapped[type] = mapped_column(...)` style with SQLAlchemy 2.0.36 (the generated models already use the classic Table API which is immune). |
| `There is no current event loop in thread 'MainThread'` | Never wrap `run_polling()` in `asyncio.run()`. The generated main.py follows the correct pattern per library. |
| `telegram.error.InvalidToken: Token is invalid` | `BOT_TOKEN` in `.env` is wrong — copy it again from @BotFather. |
| `ModuleNotFoundError: No module named 'bot'` | Run from the project root (`python main.py`), not from inside `bot/`. |
| Bot doesn't answer commands in groups | Disable group privacy via @BotFather → /setprivacy, or add the bot as group admin. |
| `FloodWaitError` / `RetryAfter` | Expected under load; the built-in anti-flood backs off exponentially and resumes. |
| Sessions lost after restart | You are on the memory/none backend. Switch to sqlite (default) or another persistent backend and regenerate. |

## Development guide — adding a new flow

1. Open `design.json` in Master Bot Maker (top bar → Open) or edit the visual project.
2. Add a **Trigger** (e.g. command `orders`) pointing at a new **Flow**.
3. Wire nodes on the canvas: SCREEN → ASK → CONDITION → DB_QUERY → END.
4. Validate (Ctrl+R), then Export (Ctrl+E) and replace this project.
5. Runtime-wise nothing else changes: `bot/flows.py` carries the graph and
   `bot/nodes/*.py` execute it — handlers never need editing.

Manual (no-generator) alternative: append the flow dict to `FLOWS` in
`bot/flows.py` and add a trigger dict to `TRIGGERS`; the engine picks both up
on restart. Node handlers for new node types live in `bot/nodes/` and are
registered in `bot/nodes/__init__.py`.

## Library quirks (python-telegram-bot v21)

- run_polling MUST be called with close_loop=False on PTB v20+.
- ConversationHandler MUST use per_message=True when entry_points contain CallbackQueryHandler (W007).
- Application MUST be built via Application.builder().token(...).post_init(...).build().
- Do NOT call asyncio.run() around run_polling().
